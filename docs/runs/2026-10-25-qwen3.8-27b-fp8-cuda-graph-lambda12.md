# 2026-10-25 — CUDA graph on Qwen3.8-27B-FP8, 2x V100-SXM2

Status: **fixed; decode improves 3.0-3.4x.**

The dense hybrid path could not capture a decode graph: the graph runner called
`init_forward_metadata_out_graph()`, `FlashAttnV100Backend` did not override it,
and the base implementation is a no-op. The Triton backend's metadata therefore
stayed `None` and capture died on `swa_out_cache_loc`.

## Root cause

`decode_cuda_graph_runner.py` calls, for every captured shape:

```python
attn_backend.init_forward_metadata_out_graph(forward_batch, in_capture=True)
```

`base_attn_backend.py` implements this as a documented no-op. The V100 backend
only implemented the legacy `init_forward_metadata_capture_cuda_graph` /
`init_forward_metadata_replay_cuda_graph` pair, which this runner no longer
calls. Eager decode worked because `init_forward_metadata()` takes a different
path and initializes the Triton backend directly.

Failure without the fix:

```
File ".../runner_backend/full_cuda_graph_backend.py", line 145, in capture_one
    swa_loc=self.forward_metadata.swa_out_cache_loc,
AttributeError: 'NoneType' object has no attribute 'swa_out_cache_loc'
```

## Fix

Add `FlashAttnV100Backend.init_forward_metadata_out_graph()`: for decode and the
speculative modes it delegates to
`self._triton.init_forward_metadata_out_graph(forward_batch, in_capture)`; other
modes fall back to the legacy capture/replay hooks. Patch:
`patches/sglang-sxm2/graph-metadata.patch` in the lab repository.

Capture then completes:

```
Capture target decode CUDA graph end. elapsed=15.47 s, mem usage=0.74 GB
```

## Results

Same stack as the FP8 run (fork `dg1kjd/sglang-sxm2` @ `73abfe1` + local
patches), fp16 KV, TP2, cold prefix, 128 output tokens, 1 warmup + 2 reps.

| Context | Graph | TTFT (s) | Prefill tok/s | Decode tok/s |
|---|---|---|---|---|
| 1K | off | 0.60 | 1666-1674 | 10.31-10.34 |
| 1K | on | 0.53 | 1906-1909 | 34.70-34.72 |
| 8K | off | 4.07 | 1972 | 10.29-10.34 |
| 8K | on | 4.00 | 2008 | 33.67-33.68 |
| 28K | off | 16.0 | 1749-1755 | 10.43-10.44 |
| 28K | on | 16.0 | 1747-1756 | 30.35-30.38 |

Decode no longer gains from the weight format; it was launch-bound. With the
graph captured, the dense path reaches 30-35 tok/s on two V100s.

## Correctness

Four greedy prompts (`France`, `Germany`, `Italy`, `Spain`) all produce the
expected continuations with the graph enabled.

One anomaly was seen once, on the first request immediately after startup: the
continuation differed (`The capital of Italy is Rome.` for the France prompt).
It did not reproduce in the four-prompt check that ran seconds later, nor in a
dedicated first-request test on a fresh start (wait for `/v1/models`, send the
same prompt twice): both responses were correct and byte-identical. Recorded as
an unreproduced observation, not as a validated behaviour.

## Where the fix lives

The change is in the fork's `flash_attn_v100_backend.py`, which does not exist
upstream at the pinned v0.5.22. It cannot enter the restomod patch queue, which
targets upstream files. Landing it properly needs the backbone fork decision;
until then it lives as a lab patch referenced by #31.

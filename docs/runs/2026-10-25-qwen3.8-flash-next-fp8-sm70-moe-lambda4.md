# 2026-10-25 — Qwen3.8-Flash-Next-FP8 expert GEMM on 8x V100-SXM2

Status: **component validated numerically; the model reaches its first
attention layer and is blocked there by the QSA decode path, not by the MoE.**

This run records two things: the block-FP8 expert method produces the same
numbers as a dequantized reference, and the full checkpoint loads on 8x V100
with the method in place. It does not record a decode throughput number,
because the first forward stops in `QwenSparseAttnBackend` (see below).

## Numeric check

`python -m sglang_restomod.quant.sm70_fp8_moe.check` builds four experts with
block-128 quantized weights, runs the method against a dequantized dense
reference, and repeats with expert-parallel drop ids (`-1`):

```
dense rel=0.00112 ep rel=0.00072 empty_nonzero=0
```

The first implementation reused the TurboMind permute helper. A probe showed
that it does not honor the `-1` drop sentinel: negative ids are bucketed into
the last expert, so expert-parallel routes would have been computed as if they
were local. The method now compacts the routed slots itself (`argsort` over the
valid ids, `bincount` offsets) and drops the matching weights, which keeps the
per-expert intermediate size at 640 on every rank.

## Model load

The first attempts failed with `CUDA out of memory` during the post-load weight
pass. Two independent causes, both fixed:

1. Inheriting `UnquantizedFusedMoEMethod` gave the layers fp16-sized
   `create_weights`; the method must derive from `Fp8MoEMethod`.
2. Replacing `layer.w13_weight` with `None` does not release the block-FP8
   source, because the loader keeps a snapshot dict of every parameter for the
   whole pass. The source is now released through the `Parameter` objects
   (`param.data = empty`), which halves the peak.

After the fixes, every rank loads at **17.29 GB**, allocates **309952** KV
tokens of fp16, and serves on port 11436.

## Where the first forward stops

```
File ".../qwen_sparse_attn_backend.py", line 178, in _resolve_flash_attn_varlen_func
ModuleNotFoundError: No module named 'flash_attn'
ImportError: QSA decode requires flash_attn (FA2), flash-attn-4 (FA4 cute),
             or aiter (ROCm) for its packed varlen fallback.
```

The QSA backend has two SM70 specializations, both keyed to a head layout of
`(6, 256)` (24 query heads at TP4, one KV head of 256). Flash-Next uses
`num_attention_heads=24`, `num_key_value_heads=2`, `head_dim=256`, so at TP8
each rank has 3 query heads: neither specialization matches, and the packed
FA2 fallback is not built for V100 (the image deliberately omits
`flash_attn_v100`). This is an attention-backend gap, tracked separately; the
expert GEMM is not involved.
